# Ubuntu 終端機設定選單

不需要圖形桌面。請使用一般使用者，在專案根目錄開啟互動式終端機（建議 UTF-8、至少 80 欄 × 24 列）。需要系統權限的安裝與 Docker 操作會另外使用 sudo；不要整個工具都加 sudo，以免設定檔變成 root 擁有。

```bash
bash ubuntu/setup.sh
```

使用 Ubuntu 內建 Python 3 curses，不另外下載 Python 套件；缺少 Python 時，入口會用 apt 安裝 python3。SSH 連線請分配終端機，例如 `ssh -t 使用者@主機`。

## 三個入口

| 入口 | 功能 |
|---|---|
| `bash ubuntu/setup.sh` | 主選單：安裝、資料庫、頁面選擇、診斷、重設 |
| `bash ubuntu/database-setup.sh` | 直接進入資料庫設定 |
| `bash ubuntu/pages-setup.sh` | 直接進入頁面勾選 |

方向鍵選擇、Enter 確定、q/Esc 返回。執行安裝／診斷時暫時回到終端機顯示紀錄，完成後按 Enter 返回。

## 安裝

先設定網站連接埠，再呼叫原有 `ubuntu/install.sh`；資料庫可先留空。Docker 與 Compose 缺少時由原安裝程式處理，保留既有設定、密碼與 PostgreSQL volume。原來的 install.sh／reset.sh 仍可單獨使用。

## 資料庫

IDCC、SPC 各四欄，須全部填妥或全部留空。選欄位按 Enter 編輯，密碼會遮蔽；可用 Ctrl+U 清空、退格刪除，Esc 放棄該欄輸入。原有複雜 .env 變數插值請使用文字編輯器維護，工具支援一般字串設定並處理密碼特殊字元。

Demo 開啟使用目前 SQL Server；關閉時切到空的 PostgreSQL，舊頁面仍需移植查詢和資料表，切換前會提示確認。單純儲存只寫本機 `.env`，「儲存並套用」會重建容器；請先完成環境安裝。測試使用容器目前已套用的設定，不會測試尚未儲存的輸入。留空的 SQL Server 在診斷中會略過，不代表連線成功。

設定檔以原子方式寫入，保留未知變數與註解，建立的 .env 權限只允許目前使用者存取；不把帳密放入命令參數或輸出。每次儲存仍請以自己的備份政策保護設定。

## 頁面勾選

↑↓ 移動、空白鍵勾選，a 全選、n 全取消、s 儲存、q 放棄返回；可用 PageUp／PageDown 快速移動。共用相同實體目錄的項目會連動選取。

使用與 Windows 相同的 `.idcc-pages.json` 和 77 項頁面目錄，原始碼保留，可重新啟用。首次更新至支援頁面開關的版本須重建映像，之後儲存後 Ctrl+F5 重新整理即可。停用頁面的 PHP 入口與其目錄內 API 回應 403；外站僅能隱藏本機入口，這不是帳號權限系統。

## 重設與檢查

重設沿用原 reset.sh，仍須輸入大寫 RESET，清除本專案容器、網路與應用映像，保留資料庫、設定、密碼、頁面勾選。

只檢查頁面設定，無需互動終端機，不安裝缺少的 Python、不改任何設定，也不顯示帳密：

```bash
bash ubuntu/setup.sh --check
```

正常會顯示 `ok: true`、頁面總數和勾選數。JSON 格式錯誤時會報錯，原設定不會被覆寫；可進頁面選單重新選擇並儲存。

## 只測試連線

介面的連線測試不再檢查業務資料表、欄位、日期範圍或首頁 API。它只建立連線，執行不涉及資料表的 SELECT 1，並在結束時關閉連線；不修改資料。SQL Server 會確認 SQLSRV 與 PDO 兩種網站使用的連線方式，單一方式失敗也會說明是哪個方式。

三個資料庫分開測試、分開顯示結果，其中一個失敗仍會繼續測其他項目。未填完整顯示「尚未設定，已略過」，不算連線成功。測試使用容器已載入的設定，修改後先儲存並套用。舊的 diagnose-db.php 為額外深入檢查工具，已不由此按鈕呼叫。
